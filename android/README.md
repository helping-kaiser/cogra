# CoGra Android

The reference frontend. See
[docs/implementation/android.md](../docs/implementation/android.md) for the
design and [android/CLAUDE.md](CLAUDE.md) for the assistant rules.

## Modules

- `core:crypto` — the client-side signing and key-backup crypto, pinned to
  the repo-root golden vectors; plain Kotlin, no Android deps.
- `core:domain` — use-cases, domain types, and the signing orchestration;
  plain Kotlin, no Android deps.
- `core:network` — Apollo client + generated operations, the encrypted
  token/identity stores, and the refresh machinery; no UI.
- `feature:onboarding` — invite check, application + key ceremony, and the
  wait-and-sign status screen.
- `feature:auth` — login, actor restore, password reset.
- `feature:home` — the signed-in shell: reciprocation prompt, husk warning,
  handshake resume.
- `feature:invites` — links, the approval queue, the on-device vouch.
- `feature:settings` — sessions, key backup, credentials, sign-out.
- `app` — application shell, navigation, DI entry point.

`core:ranker` lands with slice 3 — see
[docs/implementation/android.md](../docs/implementation/android.md).

## First-time setup

The Gradle wrapper is committed, so `./gradlew` works out of the box. Point
the build at your Android SDK with `android/local.properties` (gitignored):

```properties
sdk.dir=/path/to/Android/Sdk
```

The build needs **two JDKs**: 17 compiles the app, and 21 launches the unit
tests — Robolectric takes its sandbox SDK from `targetSdk`, and the API 36
sandbox will not start below Java 21. Gradle picks each by language version
from the JDKs it auto-detects, so both simply have to be installed; Android
Studio's bundled JBR is a 21. Check what Gradle can see with:

```bash
./gradlew -q javaToolchains
```

## Build, test, run

```bash
./gradlew :app:assembleDebug          # build the app
./gradlew test                        # JVM unit tests (all modules)
./gradlew :app:installDebug           # install on a running emulator/device
```

The first `test` run pulls Robolectric's android-all sandbox jars — about
600 MB, one per API level the suites launch on — and stages them under
`build/robolectric-sdks`. Gradle resolves them like any other dependency, so
later runs (including `--offline` ones) need no network at all. Bumping
`robolectric` in `gradle/libs.versions.toml` means bumping the `androidAll*`
versions beside it; a mismatch fails the run with the missing jar's name.

The GraphQL client is generated by Apollo Kotlin from the repo-root
`../schema.graphql` (the checked-in backend contract) during the
`:core:network` build — never hand-edit generated code.

## Pointing the app at a backend

Start the backend with `make dev` from the repo root before the hand test.
The endpoint is configurable via `cogra.graphqlUrl` — set it in
`android/local.properties` (gitignored) or pass `-Pcogra.graphqlUrl=…`. The
default targets `http://10.0.2.2:8080/graphql`, the host loopback as seen from
the Android emulator.

`cogra.webOrigin` (default `https://cogra.example`) sets the web origin
behind shareable links (auth.md "Link URLs"): its host becomes the App-Links
host for `/join/<id>`, and share sheets compose URLs against it. App-Link
verification needs the real deployed origin; in dev, drive a link into the
app with `adb shell am start -a android.intent.action.VIEW -d "<url>" com.cogra.app`
or paste it into the invite screen.

On a **physical device** `10.0.2.2` is meaningless, so tunnel the host's port
to the device and point the app at `localhost` (already cleartext-permitted):

```bash
adb reverse tcp:8080 tcp:8080
./gradlew :app:installDebug -Pcogra.graphqlUrl=http://localhost:8080/graphql
```

A **guest's phone** has no cable and no trust in the dev machine, so it goes
through the web dev server instead: `make guest-apk` from the repo root points
the app at `<WEB_ORIGIN>/graphql` and trusts the mkcert CA that
`scripts/stamp-net.sh` stages at `app/src/devCa/res/raw/cogra_dev_ca.pem`.
That CA is per-machine and gitignored; without it the debug build keeps the
config in `src/main`, and `make guest-apk` says which command produces it. See
[development.md](../docs/implementation/development.md#reaching-the-web-dev-server-from-the-phone).
